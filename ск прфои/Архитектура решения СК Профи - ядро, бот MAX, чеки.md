# Архитектура решения для СК «Профи» v2

## Ядро + бот MAX + n8n + распознавание чеков

Подготовлено для Глеба. Версия с ответами на вопросы по n8n, LLM, ролям, дедлайнам, кнопкам и хранению.

# 1. Ответы на твои вопросы (быстрые, до деталей)

## 1.1. n8n — подходит ли?

**Да, n8n работает с MAX.** MAX шлёт webhook → n8n принимает через Webhook-node. Ответы обратно в MAX — через HTTP Request-node к MAX Bot API.

**Что n8n берёт на себя:**

- Приём сообщений/фото из MAX (webhook).
- Маршрутизация сценариев (чек, техника, дедлайн, вопрос бригадиру).
- Запись/чтение Google Sheets (нативная нода).
- Вызов LLM API (HTTP-node или нода OpenAI/Anthropic).
- Отправка сообщений/клавиатур обратно в MAX.
- Генерация PDF по объекту (через ноду или вызов внешнего сервиса).

**Что n8n НЕ берёт (или берёт плохо):**

- Сложные многошаговые диалоги с памятью. Без хранилища состояний каждый шаг превращается в спагетти.
- Ролевая модель в реальном времени — проще, если n8n перед стартом сценария ходит в Google Sheets за ролью пользователя.

**Вывод:** n8n — отлично как оркестратор пилота. Для сложной логики диалогов подключаем Redis или простую БД состояний (можно даже лист в Google Sheets: `user_id | текущий_шаг | объект_id`).

## 1.2. MAX — бизнес-аккаунт и создание бота

**С личного (обычного) аккаунта создать бота нельзя.**

- Нужен бизнес-аккаунт с ИНН организации (ООО или ИП).
- Регистрация на business.max.ru → верификация через Госуслуги → модерация до 48 часов → токен в разделе «Интеграция».
- У СК «Профи» есть ИНН? Если да — дело 1 дня. Если нет ИП/ООО под строительство — это вопрос к Женьке.

**Запасной вариант:** если с MAX ИНН проблема или модерация тянется — пилот можно сделать в Telegram (ты уже делал на TypeScript), а MAX подключить позже без переделки логики (только endpoint webhook меняется).

## 1.3. LLM — локальная или API? Платная/бесплатная?

**На старте — API. Локальная — позже, если нужна полная автономия.**

| Провайдер | Для чего | Примерная цена | Примечание |
| --- | --- | --- | --- |
| **YandexGPT Vision** | Распознавание + структуризация чеков, дедлайнов | ~180₽/млн ввод, ~540₽/млн вывод | Русский язык, принимает фото, легко через HTTP в n8n |
| **GigaChat (Сбер)** | Тот же набор + ИИ-ассистент | Бесплатный тариф с лимитами | Может не хватить лимитов на активный объект, но на пилот — ок |
| **OpenAI GPT-4o mini** | Структуризация текста, ответы бригадирам | ~$0.15/$0.60 за 1M токенов | Нужен VPN/прокси, но дешево и быстро |
| **Anthropic Claude** | Тяжёлая логика | Дороже OpenAI, нужен VPN | Отец говорил, но для пилота — избыточно |
| **Ollama (локально)** | Полная автономия | Только сервер | Нужен GPU, иначе 10–30 сек на ответ. На 2 vCPU/4GB не вариант |

**Рекомендация для пилота:** YandexGPT Vision. Чеки на русском, цены в рублях, интеграция одним HTTP-запросом из n8n. На 100 чеков в месяц — копейки.

## 1.4. ИИ-ассистент в чате (общается с бригадиром)

**Реализация:** в n8n — отдельная ветка «Вопрос бригадиру».

- Бригадир пишет что-то не по форме (не кнопка, а произвольный текст).
- n8n проверяет: если текущий шаг = «ожидание ответа» → отправляет текст в LLM API с системным промптом: "Ты помощник прораба СК Профи. Отвечай по стройке, материалам, технологиям. Если вопрос про деньги или смету — переадресуй Женьку."
- Ответ LLM уходит бригадиру в MAX.
- **Это не локальная ИИ на старте** — это вызов API (YandexGPT/GigaChat). Локально — только если купим GPU-сервер.

## 1.5. Дедлайны / планировщик (начальник пишет «до 7 числа залить фундамент»)

**Сценарий:**

1. Женя (или прораб) пишет в бот: «До 7 числа залить фундамент на Матросова».
2. n8n ловит текст → LLM-node структурирует в JSON: `{работа: "заливка фундамента", дата: "2025-10-07", объект: "Матросова", автор: "Женя"}`.
3. Бот показывает Жене карточку: «Задача: заливка фундамента, срок 07.10, объект Матросова. Подтвердить?» (кнопки Да/Исправить).
4. После подтверждения — запись в Google Sheets (лист «Задачи») + уведомление в MAX исполнителям (бригадам), привязанным к объекту.
5. За день до дедлайна — напоминание.

**Кто может ставить задачи:**

- **Admin** (Женя) — любые задачи на любой объект.
- **Manager** (Виктор/прораб) — задачи на свои объекты.
- **Worker** (бригадир) — может поставить задачу своей бригаде, но она попадает на подтверждение менеджеру (опционально).

## 1.6. Кнопки в MAX — reply keyboard (под полем ввода)

**Верно.** Inline-кнопки (внутри сообщения) легко подделать callback-запросом. Reply keyboard (кнопки под строкой ввода) — безопаснее для рабочих процессов.

- В MAX Bot API это параметр `reply_keyboard` (массив кнопок).
- n8n отправляет его в JSON теле запроса к `/messages`.

## 1.7. Кто добавляет сотрудника? Admin или менеджер?

- **Admin (Женя)** добавляет manager'ов и admin'ов.
- **Manager** может добавлять worker'ов (рабочих, бригадиров, операторов техники) — это разгружает Женьку.
- **Worker** не добавляет никого.
- Меню: «Управление» → «Добавить сотрудника» → ввод MAX user_id → выбор роли → запись в Google Sheets.

## 1.8. Объекты — кто создаёт?

- **Только admin (Женя)** создаёт объект. Это стратегическое решение: калькуляция, договор, бюджет.
- Если Виктор присылает чек, а объекта ещё нет — бот предлагает «Запросить создание объекта у Женьки». Женя получает уведомление, создаёт объект, Виктору приходит «Объект создан, пришлите чек повторно».

## 1.9. Где хранится результат? Таблица или PDF?

**Оба.**

- **Оперативно:** всё в Google Sheets (приход-расход, техника, задачи). Женя видит цифры в реальном времени.
- **По закрытию объекта:** n8n собирает данные из Sheets → генерирует **PDF-отчёт** (стилизованный документ: калькуляция, чеки, техника, задачи, итог) → сохраняет на Яндекс Диск. Это профессионально для заказчика и для архива.
- PDF можно генерировать через ноду `n8n-nodes-pdf` или через Google Docs API (заполняем шаблон → экспорт в PDF).

## 1.10. Prisma — нужна?

**На старте — нет.** Google Sheets заменяет БД для пилота.
**Но:** если ты привык к Prisma и хочешь видеть схему — я ниже нарисовал `schema.prisma` для этапа 3 (переход на PostgreSQL). Это полезно как документация модели данных даже без запущенной БД.

## 1.11. PostgreSQL vs Google Sheets

- **Этап 1–2 (пилот):** Google Sheets. Женя привык к таблицам, n8n пишет туда напрямую, нулевая задержка.
- **Этап 3+:** PostgreSQL + Prisma. Когда объектов станет много и Sheets начнёт тормозить. Миграция простая: n8n начинает ходить в PostgreSQL вместо Sheets.

│ Яндекс Диск      │  │ Google Sheets  │  │ PostgreSQL         │

**Почему так:**

- n8n визуально показывает поток данных — тебе удобно править без программиста.
- Google Sheets на старте = ноль времени на администрирование БД, Женя видит всё привычным способом.
- PostgreSQL подключается позже без переделки логики — меняется только нода в n8n (Google Sheets → PostgreSQL).

# 4. Ядро: модель данных вокруг Агента

## 4.1. Справочник Агентов (Google Sheets / будущая таблица `agents`)

| Поле | Пример | Комментарий |

| status | active / paused / archived |  |

**Одним справочником закрываем:** бригады людей, свою технику (КамАЗ, самосвал, вышка), партнёрскую технику (кран, экскаватор), поставщиков, почасовую рабочую силу.

## 4.2. Пользователи и роли (whitelist)

| Поле | Пример |
| --- | --- |
| user_id (MAX) | 123456789 |
| role | admin / manager / worker / guest |
| name | Виктор |
| linked_agent_id | A-005 (если Виктор = агент-поставщик) |
| added_by | admin_user_id |
| added_at | дата |

**Кто добавляет:** admin — manager'ов и admin'ов. manager — worker'ов. guest добавляется автоматически при первом входе.

// schema.prisma — для этапа PostgreSQL

  title       String
  deadline    DateTime?

  status      TaskStatus @default(PENDING)
  createdBy   String   // MAX user_id автора

model ObjectAgent {
  id        String   @id @default(uuid())

  objectId  String
  agent     Agent    @relation(fields: [agentId], references: [id])
  agentId   String
  roleOnSite String  // например "подрядчик фундамента"

  ACTIVE
  PAUSED
  ARCHIVED
}

enum ObjectType {
  IZS
  PROM
  MAGAZIN
  ZABOR
  FASAD

enum ObjectStatus {
  PROJECT

  CLOSED
}

enum CheckStatus {
  NEW
  CONFIRMED
  DISPUTED
}

enum TaskStatus {
  PENDING
  IN_PROGRESS
  DONE
  CANCELLED

# 5. Логика бота в MAX (уточнённая)

## 5.1. Регистрация

1. Женя регистрирует бизнес-аккаунт на business.max.ru (нужен ИНН организации).
2. Создаёт бота, получает токен.
3. В n8n создаётся Webhook URL, который прописывается в настройках бота MAX.

## 5.2. Первый вход (user_id → роль)

```javascript
/start
   │
   ▼
user_id есть в whitelist (Google Sheets)?
   │
   ├── НЕТ ──► Приветствие + reply-клавиатура:
   │            [Услуги компании] [Оставить заявку]
   │            Гостю показываем текст из сайта (черновик уже есть).
   │            Заявка = имя, телефон, тип объекта → строка в Sheets + уведомление admin.
   │
   └── ДА ───► Роль из Sheets:
                ADMIN  → полное меню (reply-клавиатура):
                         [Прислать чек] [Техника] [Задачи]
                         [Объекты] [Агенты] [Добавить сотрудника] [Сводка]
                MANAGER → [Прислать чек] [Техника] [Задачи]
                         [Объекты] [Добавить рабочего]
                WORKER  → [Прислать чек] [Отчитаться о смене]
                         [Мои задачи] [Статус работы] [Задать вопрос]
```

## 5.3. Добавление сотрудника (меню для admin/manager)

```javascript
Admin жмёт [Добавить сотрудника]
   │
   ▼
Ввод MAX user_id (или пересылка контакта из MAX)
   │
   ▼
Выбор роли (reply-клавиатура): [Рабочий] [Менеджер] [Администратор]
   │
   ▼
Привязка к агенту (опционально): [Бригада Иванова] [Новый агент]
   │
   ▼
Запись в Sheets «Пользователи» + уведомление новому: "Вас добавили в СК Профи"
```

## 5.4. Чек (пилот)

```javascript
Worker/Manager жмёт [Прислать чек]
   │
   ▼
Выбор объекта (reply-клавиатура: список активных из Sheets)
   │ (если объекта нет → «Нет доступных объектов. Обратитесь к Жене»)
   ▼
Отправка фото чека
   │
   ▼
Фото → n8n → Яндекс Диск (в папку объекта)
   │         → YandexGPT Vision (OCR + JSON)
   │         → Категоризатор (крупные категории)
   │
   ▼
Бот показывает карточку:
  "📄 Чек распознан:
   Дата: 15.03
   Категория: Метизы
   Сумма: 4 820 ₽
   Объект: Матросова
   Всё верно?"
   [Да, записать] [Исправить] [Отмена]
   │
   ├── [Да] → запись в Sheets «Приход-расход» + уведомление Женьке
   ├── [Исправить] → меню выбора категории (reply-клавиатура) + поле для суммы
   └── [Отмена] → удаление с Диска (опционально)
```

**Если у Виктора нет объекта:** он пишет Жене, Женя создаёт объект через меню [Добавить объект] (только admin), потом Виктор шлёт чек.

## 5.5. Техника (этап 2)

```javascript
Operator жмёт [Отчитаться о смене]
   │
   ▼
Выбор техники (reply-клавиатура: привязанная к агенту/оператору)
   │
   ▼
Ввод часов (или кнопки: [4 часа] [8 часов] [Смена])
   │
   ▼
Бот считает: часы × ставка из справочника Агентов
   │
   ▼
"Кран Liebherr, 8 часов × 2 500 ₽ = 20 000 ₽. Верно?"
   [Да] [Исправить]
   │
   ▼
Запись в Sheets «Техника» + уведомление менеджеру
```

## 5.6. Дедлайн / задача (этап 2)

```javascript
Admin/Manager пишет текст: "До 7 числа залить фундамент на Матросова"
   │
   ▼
n8n распознаёт, что это не команда кнопки → отправляет в LLM (YandexGPT)
   │
   ▼
LLM возвращает JSON:
{
  "type": "task",
  "work": "заливка фундамента",
  "deadline": "2025-10-07",
  "object": "Матросова",
  "confidence": 0.92
}
   │
   ▼
Бот показывает карточку:
  "📋 Задача распознана:
   Работа: заливка фундамента
   Срок: 07.10.2025
   Объект: Матросова
   Подтвердить и разослать бригадам?"
   [Подтвердить] [Исправить] [Отмена]
   │
   ▼
[Подтвердить] → запись в Sheets «Задачи» → уведомления исполнителям объекта
```

## 5.7. ИИ-ассистент (ответ бригадиру)

```javascript
Worker пишет произвольный текст (не по кнопке)
   │
   ▼
n8n проверяет текущий шаг пользователя:
   │
   ├── Если шаг = "ожидание_ввода" (например, ввод часов) → обрабатываем как данные.
   └── Если шаг = "idle" (ничего не ждём) → отправляем в LLM с системным промптом:
       "Ты опытный прораб СК Профи. Отвечай кратко по делу.
        Если вопрос про смету, деньги, сроки — скажи обратиться к Жене."
       │
       ▼
       Ответ LLM → бригадиру в MAX.
       Лог вопрос+ответ сохраняется в Sheets «Лог ИИ» (для контроля качества).
```

## 5.8. Уведомления

- **Женек:** вечерняя сводка (чеки за день, техника, новые задачи, заявки гостей).
- **Менеджер:** чек в "Разборе" (распознан с низкой уверенностью).
- **Worker:** новая задача, напоминание за день до дедлайна.
- **Guest:** "Заявка принята, перезвоним" + карточка заявки админу.

# 6. Распознавалка чеков (через n8n)

## 6.1. Конвейер в n8n

```javascript
Webhook (фото чека)
   │
   ▼
[Node: HTTP Request] → сохранить фото на Яндекс Диск (в папку объекта)
   │
   ▼
[Node: HTTP Request] → YandexGPT Vision API
   Payload: {modelUri="gpt://b1.../yandexgpt/latest",
             messages=[{role="user", text="Распознай чек. Верни JSON:
             {date, seller, total, items:[{name,qty,price}], category}"}],
             attachments=[{data=photo_base64}]}
   │
   ▼
[Node: Function] → парсинг JSON ответа LLM
   │
   ▼
[Node: Function] → категоризатор (схлопывание позиций в крупные категории)
   Правила: метизы, бетон, арматура, ГСМ, кровля, электрика...
   │
   ▼
[Node: Google Sheets] → запись строки
   │
   ▼
[Node: HTTP Request] → MAX API (карточка чека пользователю)
```

## 6.2. Категории чеков (начальный словарь — утвердить с Женьком)

1. Бетон / раствор
2. Арматура / металлопрокат
3. Метизы (одной строкой: саморезы, гвозди, дюбели, анкера)
4. Кладочные материалы (кирпич, блок, шлакоблок)
5. Сэндвич-панели
6. Кровельные материалы / ПВХ-мембраны
7. Гидроизоляция / утеплитель
8. ГСМ / солярка / масла
9. Запчасти и ремонт техники
10. Электрика / кабель
11. Сантехника / канализация / водоснабжение
12. Инструмент / оснастка / спецодежда
13. Доставка / перевозка / аренда
14. Прочее

## 6.3. Контроль качества

- **Пилот:** 1–2 реальных объекта, сверка с ручным подсчётом Женька.
- **Метрики:** точность категории ≥ 9/10; чек в таблице в день покупки.
- **Разбор:** чеки с confidence < 0.8 попадают в лист "Разбор" — Женя одной кнопкой подтверждает или правит.
- **Дообучение:** спорные чеки + правки Женьки = датасет для уточнения промпта LLM.

# 7. Сервер

## 7.1. Конфигурация

| Компонент | Ресурс |
| --- | --- |
| VPS | 2 vCPU / 4 GB RAM / 60 GB NVMe |
| ОС | Ubuntu 24.04 |
| Контейнеры (Docker Compose) | n8n, PostgreSQL (этап 3+), Redis (состояния диалогов), Nginx |
| HTTPS | Let's Encrypt |
| Стоимость | ~600–900 ₽/мес (например, Timeweb Cloud, RUVDS, Selectel) |

## 7.2. Почему без GPU

- OCR и LLM — через облачные API (YandexGPT, GigaChat), а не локально.
- n8n + PostgreSQL + Redis на 4 GB влезает комфортно.
- GPU нужен только если захотим локальную LLM — тогда апгрейд сервера или отдельная машина.

## 7.3. Бэкапы

- Ежедневный снапшот VPS (автоматически у провайдера).
- Google Sheets и Яндекс Диск и так в облаке.
